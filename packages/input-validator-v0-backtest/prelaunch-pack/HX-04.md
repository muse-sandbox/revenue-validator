# HX-04 — pre-launch карточка
(без идентификаторов источника)

## Контекст и цель
Цели: (1) увеличить выручку за счёт продажи фич, доступных в мобильном приложении; (2) промоутировать приложение той части аудитории, у которой есть только веб-аккаунты. Основание: tour update внутри приложения — устоявшаяся практика и источник дополнительной выручки; приложение выпускает интересные фичи, о которых веб-пользователи могут не знать. Идея проекта — информировать веб-пользователей об этих фичах и одновременно пытаться продавать их в связке с приложением. План изначально серийный: последовательно протестировать несколько вариантов tour update на примере фичи Practice Mode; допускается и комбинированный подход для большего вовлечения.

## Предлагаемое изменение (что именно меняем, для кого, где)
Итерация 1: на странице таба (desktop web) добавляется кнопка «Practice Mode» рядом с кнопкой Official Tab. По клику — модальное окно с описанием Practice Mode, QR-кодом (работает и для iOS, и для Android) и кнопками скачивания приложения из сторов. Проверяется CR кнопки на странице таба. Дополнительно: трекинг пользователей в приложении, пришедших из веб-tour-update, передача песни/таба, с которого пришёл пользователь, и проведение его через referral-тур.

Итерация 2 (запланирована заранее как следующий шаг серии): запуск тура при посещении 2-й страницы в сессии. Показывается модальное окно с update-туром, объясняющим новую фичу приложения (несколько слайдов-«хуков»: Chords, AI, Playback); после описания фич показывается чекаут; продаётся trial PRO-доступ вместе с доступом к Practice Mode в приложении за $99.99 (лендинг с чекаутом открывается в новой вкладке, подсвечивается ценность Practice Mode); после покупки — success-экран с призывом скачать приложение. Если пользователь не переходит в приложение, у него остаётся полный доступ к Pro-фичам на вебе. Стили и копирайтинг — на базе прошлого проекта с update-туром приложения.

## Аудитория / платформа / сценарий
Desktop web. Итерация 1: пользователи, просматривающие страницу таба (стартовое событие — просмотр таба). Итерация 2: пользователи, открывающие вторую страницу (второй таб) в сессии. Отдельных ограничений по гео/статусу подписки в документе — missing.

## Baseline
Tab View → access = 0.11% (базовое значение целевой метрики в обеих итерациях; в модельной таблице итерации 2 записано как «011%» — очевидная опечатка документа, в плане теста той же итерации указано 0.11%).

## Reach
- Итерация 1: 256,105 Tab View на вариацию (модельный период; горизонт явно не подписан — по сопоставлению с forecast-таблицами похоже на суточный объём ~270k просмотров, но в модели период не назван — assumption).
- Итерация 2: 209,246 Second Tab View на вариацию (аналогично без явного горизонта).

## Денежная модель (цепочка поведение→деньги, все коэффициенты)
Итерация 1: Tab View → referral-инсталлы приложения (только в B): 338 инсталлов; 8% инсталлов → access, т.е. +27 accesses; +16 charges. Web accesses + referral: 274 → 301 (+27); web charges + referral: 155 → 171 (+16). Tab View → access: 0.11% → 0.12% (+10%). Revenue: $10,602 → $11,287 (+$685); формула добавленной выручки в документе: `(9313.54+2667.98)/(218.29+61.43)*16+10602` (средний чек как отношение сумм выручки к числу charges по двум неподписанным компонентам × 16 доп. charges — коэффициенты в документе не расшифрованы). ARPPU: $68 → $66 (−$2); ARPU: $0.041 → $0.044 (+$0.003, +6%).

Итерация 2: Second Tab View 209,246; accesses 234 → 257 (+23); charges 137 → 151 (+14); Tab View → access 0.11% → 0.12% (+10%); Revenue $9,151 → $10,066 (+$915); ARPPU $67 → $67 ($0.0); ARPU $0.044 → $0.048 (+$0.004, +10%).

## Ожидаемая incremental revenue и горизонт
Итерация 1: +$685 на модельный период (горизонт явно не подписан — вероятно сутки, assumption). Итерация 2: +$915 на модельный период (аналогично). Годовая/иная экстраполяция — missing.

## Допущения и их коэффициенты (каждое с типом)
- Baseline Tab View → access 0.11% — observed fact.
- 338 referral-инсталлов из Tab View (только в B) — assumption (источник числа в документе не приведён).
- 8% конверсия app referral install → access — коэффициент из прошлого опыта QR-перехода веб→приложение (см. Evidence); перенос на этот сценарий — assumption.
- Лифт +10% accesses (в обеих итерациях) — forecast-model / author opinion (гипотеза).
- ARPPU неизменен (итерация 2: $67 → $67; итерация 1: $68 → $66, лёгкое снижение из-за структуры referral-чеков) — assumption.
- Средний чек добавленных charges по формуле `(9313.54+2667.98)/(218.29+61.43)` — forecast-model, компоненты не расшифрованы.
- Цена оффера итерации 2 — $99.99 за trial PRO + Practice Mode — заданный параметр решения (observed fact как параметр дизайна).
- Инкрементальность добавленных accesses (отсутствие каннибализации обычных веб-покупок) — implicit assumption, в документе не обсуждается.
