# RECOMMENDATIONS FOR VALIDATOR V1 (по итогам unblind-оценки FLOW-571)

Предварительное решение (ждёт human confirmation): **включать KB в Validator V1 с доработками ниже** — не «как есть» и не отказ. Основание: 4/4 слепых предпочтений KB-плеча, 4/4 новых source-grounded инсайтов, 0 hallucinations / 0 unsupported transfers, при двух выявленных систематических слабостях.

## Доработки knowledge base (V0 → V1)

1. **Scope-note к IKB-P09 (обязательно).** Дописать границу: «"Ценовой рычаг не двигает ex" замерен на НЕисчерпанных ex при доступном re-trial (KS-06 iter2). По исходу эксперимента 7487 (2026-05): терминальный one-time deep-discount ($19.99) на исчерпанном winback-сегменте дал member→buyers +365.6% iOS / +103.8% Android и rollout — паттерн НЕ распространяется на сегмент, явно отвергший полный прайс». Без этого V1 будет систематически недооценивать терминальные ценовые офферы для ex.
2. **Новый паттерн: скоупинг goal-метрики к затронутой поверхности.** Урок эксперимента 7712 (IH-04): «surface-scoped treatment нельзя судить по Total ARPU — метрика, где затронутая поверхность даёт 12–17% выручки, структурно не может увидеть эффект; sizing и judgement — на сегменте, которого касается treatment». Ни одно плечо этот дефект не поймало; паттерн закрывает главный пробел V0. Кандидаты-источники: страница 811868738 + (для V1-корпуса) страницы 773658792, 788612067, 788613565 после их включения.
3. **Новый паттерн: доставка/экспозиция как pre-launch gate (усиление IKB-P11).** Урок 7454 (IH-03): iOS-плечо фактически не запустилось (реальный объём 3 дня, затем 1–3 users/день) — «No iOS reading is possible». Добавить в P11 требование канареечной проверки доставки в первые 24–48 часов с явным stop-rule, а не только пре-запусковый замер fail-rate.
4. **Новый паттерн-кандидат: «персонализировать оффер, а не обёртку».** Урок 7454: message-only персонализация не двигает интент (paywall→click ×0.5 — «wins curiosity but loses intent»). Согласуется с уже существующим выводом B «все крупные лифты линии — сегмент+оффер»; после включения 7454 в корпус становится источником.
5. **Обновление корпуса.** Включить в V1 карточки четырёх holdout-экспериментов (они перестали быть holdout): 7160/7187, 7487, 7454, 7712 — с обычной процедурой traceability. Для следующего цикла оценки понадобится новый holdout.

## Доработки протокола оценки (для следующего A/B)

6. **Нейтрализация маркеров плеча в blind-фазе.** Постпроцессинг ответов перед сборкой пар: убрать самодекларации («плечо B», «Knowledge context не предоставлен») и, в идеале, выдать ревьюеру манифест без per-file хэшей пар (интегрити проверяет отдельный агент). Иначе «слепота» остаётся только слепотой к исходам.
7. **Разделить генератор и судью.** Оценку выполнял агент той же модели, что генерировала оба плеча; в следующем цикле — независимый судья (другая модель или человек) хотя бы для C4.
8. **Митигировать якорение на корпус.** В prompt ревью-прохода добавить явный шаг «сначала список рисков ИЗ САМОЙ карточки без KB, затем сверка с KB» — по следу IH-03, где KB-плечо упустило anchor-validity инсайт, найденный плечом A.
9. **C7 мерить на человеке.** Зафиксировать фактическое время человеческого ревью пары (сейчас только агентная оценка ~4 мин/кейс при 15–18 стр. на пару); при систематическом превышении 10 минут — сокращать формат ответа валидатора (executive summary + приложение).

## Что сохранить как есть

- Дисциплина source ID + статусы [факт]/[интерпретация]/[гипотеза переноса] + single-case пометки: 0 hallucinations и 0 unsupported transfers на 4 кейсах — прямой результат этих правил.
- Сохранение противоречий корпуса без усреднения (IKB-P12): в IH-01 ровно это дало корректное «знак непредсказуем → guardrail с порогом», подтверждённое исходом (Android var3 retention значимо вниз).
- Правило «переносится механизм, не числа» — ни одного переноса величин в 4 ответах.
