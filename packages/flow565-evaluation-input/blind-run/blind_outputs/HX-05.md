# ПРОХОД 2: КРИТЕРИИ И РЕКОМЕНДАЦИЯ

## 1. Рекомендация + уверенность
**`revise`, уверенность medium** — положительный прогноз держится на неизмеренном коэффициенте возврата платящих (S7c,d) и не содержит ни одной строки потерь при том, что вариация C перестраивает поверхность с соседними денежными потоками $800 (S3), а sample недостижим за 21 день (S5, S10).

## 2. Краткое обоснование
Идея денежно осмысленна: замеренная воронка (S4) показывает, что тур пропускает лишь 70% при 65% доходимости (S7a,b), т.е. ~19–20% входящих теряются до paywall — это реальный fact. Но переход от «потерянных пользователей» к «+$492 revenue» требует допущения, что отвалившиеся на туре конвертились бы с той же CVR, что и прошедшие, — это нигде не замерено и уязвимо к selection bias (низкоинтентные уходят на туре). Для C добавлен коэффициент «+5%» уровня «we can assume» (S7d) и regwall, потери от которого не оценены вовсе (S8). Дизайн требует 272 909 × 3 группы = 818 727 пользователей за 21 день (≈38 987/день), тогда как замеренный потолок поверхности ≈27 478 unified/день (S5) — sample недостижим даже при 100% аллокации. Всё это исправимо до запуска.

## 3. Ожидаемая incremental revenue
- **Прогноз автора:** +$492 (B) / +$520 (C) поверх $2 460 на когорту 25 463 tab views; горизонт — `missing` (S6, S14-2).
- **Реалистичный диапазон валидатора, B:** [≈$0; +$492] на ту же когорту — верхняя граница = модель автора (100% возврата отвалившихся), нижняя = замена необоснованного S7c на 0 (документ не содержит замера интента отвалившихся на туре); механика B (удаление шага при неизменных цене и соседних кнопках) ограничивает потери снизу вблизи нуля.
- **C:** диапазон не восстановим, потому что документ не содержит данных для оценки двух минусов: (i) эффекта regwall и единого модала на текущие 51 покупку базовой воронки и (ii) каннибализации соседних воронок страницы (Official Tab $492 + UG Tab Tools $308 = $800 на ту же когорту, S4) при перекрытии Print/copy новым модалом. Верхняя оценка потерь из собственных данных документа — до $800, что превышает прогнозируемый gain $520.

## 5. Критичные допущения (на которых держится положительный impact)
- S7c (forecast): отвалившиеся на туре 19–20% конвертились бы с той же CVR, что прошедшие → весь gain B ($492).
- S7d (assumption): «+5% спасённых» от спрямления до plans → весь дополнительный gain C ($28).
- S7e (assumption): ARPPU $82 неизменен во всех вариациях, включая C с новым платёжным слоем.
- S6 (forecast): перенос Access→Charges в модели (30→36/37) сохраняет текущую trial→charge пропорцию — не обсуждён при том, что S14-3 фиксирует разрыв purchased 51 / charged 30.

## 6. Риски каннибализации / refunds / guardrails
- Каннибализация: единый upgrade-модал C накрывает Print и copy и соседствует с воронками Official Tab ($492) и UG Tab Tools ($308) на той же странице (S3, S4) — перераспределение кликов без прироста purchases возможно; числом не оценено (S8).
- Regwall (C): новый барьер до платёжного слоя может срезать часть текущих 51 покупок — риск отрицательного знака для C, не смоделирован.
- Refunds/reconversion/LTV: `missing` (S8); prefill платёжных данных + «ambulance» pop-up + спрямлённый чекаут — классический профиль роста импульсных покупок и refunds, в документе не затронут.
- Guardrails не объявлены (S9): нечем поймать деградацию соседних воронок и refund rate во время теста.

## 7. Stop-rule
В документе отсутствует (S13). **Предложение валидатора:** остановка вариации C при статистически значимом падении суммарной purchases-конверсии поверхности таба (базовая воронка + Official Tab + UG Tab Tools, метрики из S4) либо росте refund rate по когорте C относительно контроля на промежуточном чтении (день 7 и день 14); B — остановка при значимом падении purchased против контроля.

## 8. Что изменит рекомендацию
В сторону `launch`:
- Строка потерь числом для C: замер доли кликов Official Tab / UG Tab Tools, перехватываемых новым модалом, + оценка эффекта regwall (хотя бы по прошлым regwall-экспериментам) — закрывает К3.
- Evidence для S7c: сегментный замер (например, CVR пользователей, попадающих в воронку в обход тура, если такой путь существует) либо честная переразметка +$492 как верхней границы с консервативным центральным сценарием — закрывает К2. Альтернатива: явно объявить эксперимент калибровочным по B без обещания $520 от C.
- Пересчёт дизайна: расчёт мощности по ARPU с фактической SD (или объявленный сегмент чтения денег — «источник Download», несущий $1 476 из $2 460 по S4), duration ≥ ceil(818 727 / 27 478) ≈ 30 дней или чтение решения по CR с деньгами как направленной проверкой — закрывает К4/К5.
- Guardrails (соседние воронки, refund rate) + stop-rule + план post-rollout измерения (holdout доля/срок или 30/90d observational) — закрывает К6.

В сторону `deprioritize`:
- Замер, показывающий, что перехват соседних потоков модалом C ≥ прогнозируемого gain, при одновременном подтверждении, что возврат платящих от удаления тура близок к нижней границе (~$0), — тогда реалистичный net ≤ 0. Для приоритизации по абсолютной величине ($492 на когорту) бизнес-порог в документе не задан — если он существует, его нужно указать явно.
