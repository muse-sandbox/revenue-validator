# ERRORS & LIMITATIONS — FLOW-586 regression evaluation

Дата: 2026-08-05. Дополняет `final_verdict.md`; наследует и переутверждает оговорки
FLOW-579 (`revenue-kb-evaluation/errors_and_limitations.md`), кроме исправленных.

1. **C7 pending → FLOW-566.** Условие «human review ≤10 мин/кейс» агентной оценкой НЕ
   закрывается. Оценки судей C7_HUMAN_MIN (40–50 мин) относятся к полной сверке цитат с KB;
   чтение пары по объёму (1 604–2 215 слов) ≈ 8–11 мин. Фиксируется как pending; фактическая
   стоимость human review измеряется в shadow pilot FLOW-566. В решающее правило FLOW-586
   C7 не входит, на `GATE: FAIL` не влияет.

2. **Неполнота слепоты (унаследованное свойство дизайна, FLOW-570 §3 / протокол §3).**
   Verbatim-ответы содержательно маркируют плечо: B цитирует source ID (T*-**, P-**),
   A прямо декларирует отсутствие KNOWLEDGE CONTEXT. Все 6 судей честно указали
   KB_BEARING_ANSWER_GUESS (6/6 совпали с mapping). Вердикты C1–C4/C6 выносились с
   фактическим пониманием, какой ответ несёт KB, но без доступа к GT и mapping. Слепота
   реально защищает от знания ИСХОДОВ, не от знания плеча.

3. **Повтор на том же holdout = regression test, НЕ независимая оценка генерализации.**
   RH-01…06 — те же кейсы, что в FLOW-579; KB V1.1 собиралась после формального NO FLOW-579
   командой, знавшей систематику ошибок этого прогона (retention-паттерн V1.1 — прямой ответ
   на неё). Совпадение содержательных метрик с FLOW-579 (C4/C1/C5 6/6) подтверждает
   отсутствие регрессии, но НЕ добавляет доказательств генерализации. Генерализация —
   только на shadow pilot FLOW-566 и новом holdout.

4. **Runner-инцидент (задокументирован, влияния на результат нет).** Первый запуск
   скрипта прогона умер на Stage 2: фоновый процесс субагента завершился ДО старта
   inference — ни один inference не начался и не завершился, ни один ответ не был
   сгенерирован и не читался. Второй запуск чистый (12/12 exit 0, тайминги в
   `run_manifest.md`). Селекции результатов инцидент не создаёт (отбирать было нечего).

5. **Одна модель везде.** Оба плеча, 6 судей, C6-верификатор и evaluator Фазы C — одна
   модель (`claude-fable-5`). Систематические слепые пятна модели (напр., трактовка
   немонетизационных сдвигов преимущественно как рисков) разделяются всеми ролями;
   независимая модельная валидация не проводилась.

6. **n=6; страта 3 узкая.** Шесть кейсов; режим «пустой L1/L2» реально тестирует только
   RH-05. Выводы по стратам — направленные, не статистические.

7. **C5 и false blockers — агентная unblind-оценка одного evaluator'а.** Определения §4–5
   применены по прецеденту FLOW-579 (блокировка с подтвердившимися причинами — не false
   blocker; так засчитаны RH-03-B и RH-05-B при успешных исходах). Спорные точки честно
   зафиксированы в `case_scorecards.md`: в RH-04 численный прогноз A был ближе прогноза B;
   в RH-05 вердикт A был ближе фактическому исходу — перевесы B в этих кейсах основаны на
   механизменных/guardrail-попаданиях, это судейское взвешивание, а не арифметика.

8. **Bootstrap-оговорки корпуса** (унаследованы из FLOW-575/578/579): составитель split видел
   исходы; builder KB видел однострочные классы исходов; GT-карточки составлены агентно по
   снапшотам Confluence без финальной сверки человеком-аналитиком.

9. **C6-счёт зависит от толкования «оговорки».** Верификатор зафиксировал защитимое
   миноритарное прочтение C6=0 для RH-04 (узкое «wrapper = message-only» + строго-
   эвиденциальное «нет валидированного purchase-лифта»); решение вести гейт по мажоритарному
   прочтению (C6=1) принято по букве frozen-протокола и прецеденту FLOW-579. Пересмотр этого
   толкования — за владельцем оценки и должен быть явным, задним числом гейт не меняется.

10. **Design-vs-Reality GT-происхождение.** C5-сверка опирается на GT-карточки FLOW-575
    (агентные выжимки страниц), а не на сырые страницы; внутристраничные противоречия
    (напр., транспонированные design-числа RH-03, расхождения bullet-vs-table RH-02)
    унаследованы в том виде, в каком их зафиксировал составитель GT.
