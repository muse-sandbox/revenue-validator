# Архитектура

Кто что делает, что такое пакет и что валидатор может и не может видеть.

## Первое, что нужно знать

**Валидатор не общается ни с чем.** Никаких инструментов, поиска, Confluence,
агента-аналитика, базы данных. Один прогон видит ровно два текста: собранный
промпт (база знаний + карточки паттернов) и разбираемую карточку эксперимента.

Это сделано намеренно, а не забыто. Прогон, способный дотянуться до исхода
эксперимента, который он разбирает, обесценил бы каждое слепое сравнение в этом
репозитории. Изоляция обеспечивается в трёх местах — правило 9 промпта,
`docs/runbook.md` и флаги запуска (`--strict-mcp-config` с пустой MCP-конфигурацией,
всё остальное в `--disallowed-tools`).

**Цена этой изоляции:** всё, что требует данных — фактический enrolment rate,
реальный охват, зрелость метрики, достаточно ли велик сегмент, — валидатор
проверить не может. Он может только назвать подозрение. Подтверждение — работа
человека или аналитики, выполняемая отдельно.

## Разделение труда

Два агента, канала между ними нет. Передача — это человек, несущий документ.

| Этап | Владелец | Почему |
|---|---|---|
| Пробовали ли это раньше? | аналитика (`hypothesis-librarian`) | У валидатора нет реестра гипотез, только корпус завершённых экспериментов |
| Верна ли механика, тот ли сегмент, что говорит корпус | **валидатор** | Его ядро и единственная неоспариваемая работа |
| Первая тревога по дизайну, из одного текста карточки | **валидатор** | Дёшево, ловится сразу, данных не нужно |
| Проверить тревогу, пересчитать базы, реальный охват, размер эффекта | аналитика (`ug-experiment-design-power`) | Нужен склад данных |
| Размещение по слотам, коллизии | аналитика (`experiment-slot-planner`) | Блокирующее «добавьте плечо B» может оказаться невозможным по расписанию |
| Разметка, события когорты и экспозиции | аналитика (`experiment-event-audit`) | Валидатор пишет здесь общие слова; у аналитика есть чеклист |
| Здоровье эксперимента на ходу | аналитика | Валидатор не участвует |
| Разбор результатов, срезы | аналитика | Валидатор не участвует |
| Вернуть исход обратно в корпус | **пока никто** | Известный пробел |

Агент-аналитик живёт в отдельном репозитории (`claude-ug-manipulator`) со своими
скиллами. Отсюда он не импортируется и не держит доступов, которыми этот
репозиторий вправе пользоваться.

## Что такое пакет

В `packages/` две директории. `current/` держит то, что валидатор использует
сегодня — одна версия, один корпус, одна policy. `history/` держит всё, что сюда
привело.

Внутри любой из них имя пакета начинается с его типа, и префикс определяет, что
может в него втекать.

### 1. Version — замороженный валидатор

Шаблон промпта, база знаний, карточки паттернов, evidence policy, линтер и
`FREEZE_MANIFEST.md` с SHA-256 по каждому файлу. Запускается сам по себе.

`version-revenue-kb-v1.6` (текущий) · `-v1.5` · `-v1.4` · `-v1.3` · `-v1.2` ·
`-v1.1` · `-v1` ·
`version-interstitials-kb-v0` · `input-validator-v0-backtest/validator-v0`

### 2. Corpus — кейсы, разбитые для честной оценки

Три физически раздельные части: `knowledge-sources/` питает версию,
`holdout-blind/` питает прогон, `ground-truth-sealed/` питает только оценку.
Плюс манифест исключений и проверка на утечку.

`corpus-interstitials` · `corpus-revenue-v1`

### 3. Run — инференс без суждения

Дословные ответы, точные входы, манифест с контрольными суммами каждого
использованного замороженного файла. Прогон никогда не открывает исходы и никогда
не решает, какое плечо было лучше.

`run-interstitials-kb-ab` · `run-revenue-kb-v1-ab` ·
`run-revenue-kb-v1.1-regression` · `run-revenue-kb-v1.2-regression` ·
`run-live-official-tabs-v1.2` (+ прогоны `-v1.3`, `-v1.3-run2`, `-v1.4`, `-v1.5`,
`-v1.6`) · `run-live-premium-default-v1.6`

### 4. Evaluation — суждение по заранее зарегистрированному протоколу

Скоркарды, метрики, ограничения, вердикт. Единственный тип, которому разрешено
открывать запечатанные исходы, и только после того, как ответы прогона заморожены.

`eval-interstitials-kb-ab` · `eval-revenue-kb-v1-ab` ·
`eval-revenue-kb-v1.1-regression` · `eval-revenue-kb-v1.2-regression`

### 5. Input — пакет, переданный изолированному агенту

`input-validator-v0-backtest` · `input-validator-v0-unblind`

Собран так, чтобы clean-room агенту не пришлось трогать ничего больше: всё, что
ему можно читать, и ничего, чего нельзя. Каждый несёт свой README с тем, что
внутри него запрещено — так, unblind-пакет содержит ground truth и потому закрыт
для любого прогона.

### 6. Policy — замороженные правила работы с доказательствами

`policy-revenue-evidence-v1`

На неё ссылаются версии, а не копируют внутрь себя, поэтому смена policy видна
как отдельное событие.

## Поток

```
corpus ──knowledge-sources──> version ──┐
   │                                    ├──> run ──> evaluation
   └──holdout-blind────────────────────-┘             ▲
                                                      │
   └──ground-truth-sealed────────────────────────────-┘
                        (только сюда, и только после заморозки ответов)
```

Чтение схемы в обратную сторону и есть утечка: запечатанные исходы никогда не
должны доходить до версии или прогона.

## Правила, на которых всё держится

**Append-only.** Замороженный пакет никогда не правится. Исправление — это новая
версионированная директория. Пути в манифесте относительные, поэтому пакеты
должны оставаться соседями.

**Текущей может быть только одна версия за раз.** Её называет `docs/CURRENT.md`.
Больше нигде — ни в этом файле, ни в README, ни в задаче Linear.

**Именование — сначала тип.** `<kind>-<area>-<version>[-<what>]`, например
`eval-revenue-kb-v1.2-regression`. Шесть типов: `version-`, `corpus-`, `run-`,
`eval-`, `input-`, `policy-`. Прочитав префикс, вы знаете, что может втекать в эту
директорию, не открывая её. Пакеты переименованы в эту схему 2026-08-08;
таблица «старое → новое» лежит в `packages/README.md`, потому что замороженные
файлы по-прежнему ссылаются на старые имена и править их нельзя.

**Доменные правила — это вход, а не код.** `context/rules/` держит то, как команда
решает на самом деле. Четыре из семи его файлов всё ещё TODO, и этот пробел —
задокументированная причина, по которой валидатор получил 2 из 5 на первом живом
кейсе: он критиковал 39-дневный дизайн, тогда как команда останавливает
эксперименты на третий день.
