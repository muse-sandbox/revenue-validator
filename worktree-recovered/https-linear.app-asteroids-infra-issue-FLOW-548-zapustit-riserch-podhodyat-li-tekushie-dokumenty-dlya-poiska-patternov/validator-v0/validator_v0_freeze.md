### Выводы sanity check (цели из задачи)

1. **Неоднозначности формата устранены:** прогон Fakedoor вскрыл неоднозначность применимости К1 к «новому офферу»; в prompt внесено уточнение «введение нового платного оффера/цены считается изменением оффера» (до заморозки). Других неоднозначностей прогоны не выявили.
2. **Критерии применяются одинаково:** правило «занижение строки потерь страхуется К2, не К3» дало согласованные разные статусы К3 у Fakedoor (pass — строка есть) и Cancellation clarity (concern — строки нет) без двойного счёта; `pass (n/a)` по К1 сработал одинаково на двух неценовых кейсах.
3. **Отсутствие выдуманных данных:** все числа в примерах прослеживаются до извлечений; `missing`-поля (reach, горизонт, guardrails, stop-rules, post-rollout план) остались `missing` и вынесены списком; реалистичные диапазоны строились только из чисел самих документов (Apple Pay: [$0; +$434]).
4. **Выводы специфичны, не generic checklist:** три кейса дали три разных профиля статусов и три разных рекомендации с разными способами исправления; на денежно-успешном кейсе валидатор не ставит no-go (требование Decision Loop к backtest), на двух проблемных заранее называет именно те механизмы, которые по dev-факту и сработали.

Prompt под независимую выборку не оптимизировался; результаты независимой выборки не искались и не открывались.
