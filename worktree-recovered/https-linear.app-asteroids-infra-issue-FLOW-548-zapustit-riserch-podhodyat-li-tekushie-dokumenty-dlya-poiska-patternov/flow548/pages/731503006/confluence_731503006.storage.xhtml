Research and Context

  • Goal: increase revenue and conversion from the mobile web
  • Foundation: 

    • introduce monetization mechanisms (microtransactions, rewarded access etc.) that better fit mobweb user's behavior and expectations 

    • we’re doing this now because only ~1% of daily users install the app, leaving a significant untapped audience

Research results

There have been attempts to sell our basic plans, but they may prove too expensive for the mobile web audience. We want to try selling features separately:

  • One-time, single-use payments, 1-day access unlocks, feature unlocks 
  • $0.99/day or $0.29/hour feature
  • 24-hour access to a song
    • package sales: 5 songs for $3.99
  • Daytime access to everything
  • Hybrid with ads: $0.99 or watch ads
  • Purchase of features or free version in the app
  • etc.

Hypothesis

If we introduce microtransactions for mobile web users, we expect that more than 1.5% of the audience will click on the paid access button, which will prove that the monetization model through microtransactions is viable.

Test Description:

  • one-sided test,
  • H0: p < p0 VS H1: p >= p0,
  • p0 (threshold) = 1.5%,
  • p1(expected real conversion) = 1.6%.

Audience

Result0.19% VS 1.5% target
Verdict❌  FAILED

  1. The new mechanisms cannibalised:

    1. "microtransaction" button: 45% of clicks on Install, 57% of total app installs, 29% of fact revenue.

    2. "watch ad" button: 35% of clicks on Install and 43% of total app installs, 25% of fact revenue.
  2. We have too few clicks on the "microtransaction" button ("Unlock for $0.99") - 0.19% (or 74 users) versus 1.5% of the planned one, that is not enough to even cover the cannibalised installs.

  3. "Watch ad" button has a higher CTR - 2.77% (or 1103 users), but this is not enough to even cover the cannibalised installs.

Conclusion

  1. Still haven't reached the number of clicks and button presses specified in the model with purchase
  2. Viewers interact better with ads, but the overall economics are even worse, so we are not testing this branch further
  3. We close the iteration as FAILED
  4. Next, we will try to show the splash screen with the microtransaction button to the maximum number of viewers
