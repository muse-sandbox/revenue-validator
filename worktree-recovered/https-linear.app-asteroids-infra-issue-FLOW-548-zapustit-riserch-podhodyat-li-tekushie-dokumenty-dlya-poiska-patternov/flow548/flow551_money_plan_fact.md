## Итоговое распределение и переклассификации

**positive 3 / neutral-negative 7 / ambiguous 2** (было в FLOW-548: 4/4/4).

Три переклассификации относительно FLOW-548:
1. **Books price (#4803): неоднозначно → neutral-negative.** Финальный замер (p=0.466, точечная оценка −3%) не подтверждает +34.5% из документа (снятый на 17-м дне), а раскатка была отменена через 11 дней — факт, отсутствующий в документе. Оговорка: sloperator меряет Total ARPU, документ — Books ARPU; но откат — самостоятельный сигнал.
2. **Cancellation clarity (#6553): неоднозначно → neutral-negative по деньгам.** Задача FLOW-551 классифицирует по incremental revenue: он отрицательный (−$100–127/д по собственной оценке документа). Rollout — UX-решение, не денежное.
3. **Pro+ price decrease (#7268): успех → ambiguous.** In-experiment ARPU незначим (CI [−3.8%; +14.9%]), post-rollout revenue плоский, когортный uplift +1.5% за 2 года. Денежный успех не доказан строгим критерием, но и вреда нет.

## Ответ на критерий полезности задачи

- **In-experiment сопоставимый денежный результат восстановим для 10 из 12** (кроме popup #5238 и winback #5547/5610 — там NM из-за недобора и сломанных данных). Из них у 4 есть CI из sloperator, у остальных — p-values из документов.
- **Post-rollout incremental revenue за 30/90 дней причинно не измерим ни для одного из 12**: rollout всегда 100% без holdout. Возможен только observational estimate (before/after с сезонными контролями); в документах он есть у одного (#7268).
- **Вывод:** ground truth для backtest валидатора = in-experiment денежные результаты + rollout/rollback-решения из `ab_experiment_history` (они надёжнее текстов документов — кейс #4803). **Обязательный post-rollout measurement (holdout или заранее описанный observational-протокол) нужно фиксировать как часть будущего процесса** — сейчас его нет.

## Ограничения

- Sloperator покрывает только часть выборки (4 замера); для 2024-х экспериментов CI восстановлены быть не могут без пересчёта сырых данных.
- «Positive» у Apple Pay опирается на сегментную значимость; Total-эффект незначим.
- Все EE-оценки (Forecast per day) — прогнозы из тестовых данных, не измеренная выручка: смешивать их с OE/CM при backtest нельзя (в таблице тип указан явно).
