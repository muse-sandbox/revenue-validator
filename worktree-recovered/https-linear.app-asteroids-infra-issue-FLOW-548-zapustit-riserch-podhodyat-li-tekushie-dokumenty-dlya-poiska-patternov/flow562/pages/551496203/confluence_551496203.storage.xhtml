Research and Context

Goal: Increase revenue with tour update mechanics

Foundation: The current Tour Update scenario functions by mandating splash screens whenever users update the app. This solution has a few drawbacks:

  • ❌ Some of the new audience won't see the tour update if they installed the app after the version with the tour was released, instead of updating from an older version
  • ❌ Pop-up screens that can't be skipped frustrate users, especially if they've accumulated several tour updates and launches in every session. Our experiments with the skipped tour showed a significant drop in conversions.
  • ❌ Showing tour updates competes with and cannibalizes similar mechanics, like sales slashes.

What we want to achieve:

  • ✅ Expand the audience for showcasing the tour update on new installs without disrupting the current scenarios for them
  • ✅ Expand the set of tour updates available for display within a single session
  • ✅ Implement mandatory display and user session interruption as an option, not a necessity, and explore potential for further experiments with a skippable tour update
  • ✅ We'll create opportunities to position tour updates as valuable content and potential expansions of content types, like content updates, educational content, etc.

Description of the Solution & Mockups

In the first iteration, we'll focus on testing the effectiveness of the placement and visuals of the new entry point and its synergy with the sales banner and other elements of the Explore screen. In the next iterations, we'll start expanding the implementation to a broader audience and add more options for promo.

Solution

  • New installs of all users which completed Tour Install
    • free users with a new install → Tour Update on the Explorer → unskippable tour → paywall
    • premium users with a new install → Tour Update on the Explorer → unskipable tour → success screen
  • There may be only 1 'story card' on the explorer
    • That means we can see only one Card triggering out Tour Update for users
  • User cannot skip triggered Tour Update from Explorer
  • We put our banner a bit further on the Explorer screen to Collections section
  • After user completed Tour Update - we put this CTA-card to the end of the list as "seen"

Flow

1 iteration

1st session:

  • Enter Explorer screen
  • Press 'Story Card'
  • Entering Smart Scroll Tour Update
  • Moving through Smart Scroll Tour Update screens
    • Free users:
      • Paywall
        • if purchased → 'All set' alert → back to oExplorer
        • if not → back to Explorer
    • Paid users:
      • Success screen → Back to explorer
  • We move card to the end of the list after it has been watched
    • We set flag 'watched' after user has reached Paywall or Success Screen
    • In case user entered Tour Update and closed the app before he reached paywall or success screen → we do not set flag 'watched' for it

2nd and future sessions:

  • The 'Story Card' is still in the end of the list if it has 'watched' flag
  • In case if there is no 'watched' flag we keep the card in the beginning of the list.
