Context

As a member of Ads team I want to maximize revenue from our advertising inventory.

Interstitials is a type of inventory we use in UG apps. It works as a temporary advertising page appearing after user opens a tab page. Interstitials work on time interval 180s - so there is no impressions if user opens tab pages iside the interval

The idea is to reduce the interval from 180s to 120s to increase number of impressions and advertising revenue


Our current interstitials logic is:

  • only on tab pages
  • interval - 180s
  • limit - 5 times per session

Research

Monitoring of ad units healt metrics for interstitials shows significant difference between Android and iOS. Graphs below show daily time series of Impressions per user metric:

Android https://redash.ultimate-guitar.com/queries/3455#6230iOS https://redash.ultimate-guitar.com/queries/3453#6221

We can see that average value for Android is about 1.45 impressions per user daily, and for iOS it is about 1.9.


There were found no such a dramatic difference in user activity by platforms.

After that the assumption was that there are some ads display issues on "our side". For example it can be poor auction set up, slow display speed etc.


To check this, the number of "real" impressions was compared to the number of "expected" impressions. The number of "expected" impressions was calculated based on current interstitials logic described in Context section.

The team have decided to test the reduction of iOS interstitials timeout from 180s to 120s because this idea is easy to implement and looks promising

Hypothesis

If we reduce iOS interstitials timeout from 180s to 120s we will get +210$ revenue upside without any bad concequences for monetization.

A/B test planning

Our expectations are following:

  • The upside in revenue in test variation will be at least 15-20% (target valuest are 500$ and 600$ for control and test variations respectively)
  • The upside in impressions in test variation will be at least 15-20% (target valuest are 140K imps and 164K imps for control and test variations respectively)
  • The list of next monetisation metrics will not be changed significantly (or monetisation revenue loses will not neglect the upside of ads revenue):
    • conversion to access
    • conversion to charge
    • ARPU
  • The list of next product metrics will not be changed significantly (calculation over string "device_id+date")
    • Tab views
    • Search Click
    • Search Success
    • Tab Versions List Open
    • Search Tab Versions Open
    • App Start
    • Shot View
    • Shot Play Click

Conclusion

Do not use test variation

The real effect on revenue is dramatically smaller than it was estimated by our hypothesis. 

It was found that the estimate was overestimated because of:

  • we estimated sessions as a time interval - if 15 minuts has passed between two events it means that this events belong to different sessions. In code the session starts with app open event and ends when user closes the app or the system do it due to lack of memory. That leads to many potential impressions are not shown - they are cutoff by current limits per session.
  • admob_fail events - some of potential impressions are cutoff by different fails

The recomendation is - to discuss the possibility of impressions logic change from "5 times per session" to "no limit per session" with current timeout of 180 s
