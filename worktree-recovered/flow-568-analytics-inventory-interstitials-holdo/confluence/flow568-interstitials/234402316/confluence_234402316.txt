## Исследование и контекст

Как член команды рекламы, я хочу протестировать гугловские веб-интерстишиалы (WEBI), чтобы помочь команде выполнить амбициозный финансовый план.

Результаты самого исследования и контекст:

Web-interstitials - полноэкранный формат рекламы, возникающий в момент перехода между страницами, т.е. он не перекрывает контент и легко закрывается нажатием кнопки "Пропустить" . 

Также он соответствует

Этот формат ограничен по частоте FC = 1/час на пользователя.

### Расчет сверху

Чтобы оценить выручку сверху требуется посчитать количество просмотров страниц вебсайта, расстояние по времени между которыми >1 часа. 

Исходим из того что WEBI не будут показываться:

При "первом" открытии сайта (показ осуществляется именно на первом переходе между страницами сайта)

На всех страницах лендинга и тура 

При просмотре шотов 

При просмотре страниц курсов

Таким образом, WEBI могут быть показаны на табовой, главной, статьях/новостях, страницах бэкинг-треков, поиска, версий и прочих "контентных" страницах.

SELECT client_id, date, cums,count(cums) as cnt, if(cnt>1,1,0) as tosum FROM (
--Для каждого клиента и даты получаем arrayJoin порядковых номеров часов, зафиксированных при посещениях страниц
SELECT client_id, date, times, diffs, cumsumm_to_hour, arrayJoin(cumsumm_to_hour) as cums FROM (
--Для каждого клиента и даты получаем массив с накопительной суммой времени между посещениями страниц, а также массив порядковых номеров часов, прошедших с первого захода на сайт
SELECT client_id, date, times, diffs, arrayExists(x -> x BETWEEN 1 AND 3600, diffs) as initials, arrayMap(x -> toInt64(x/3600), diffs) as to_hour, cumsumm, arrayMap(x -> toInt64(x/3600), cumsumm) as cumsumm_to_hour FROM (
--Для каждого клиента и даты получаем массивы меток времени посещения страниц и разницу во времени между посещениями
SELECT client_id, date, count(*) as events, groupArray(datetime) as times, groupArray(hour) as hours, groupArray(toUnixTimestamp(datetime)) as timestamps, arrayDifference(timestamps) as diffs, arraySum(diffs) as summ, toInt64(summ/3600) as cnt, arrayUniq(hours) as cnt_hours, arrayCumSum(diffs) as cumsumm FROM (

-- Извлекаем сырые данные
SELECT *,toHour(datetime) as hour
FROM default.ug_rt_events_web
WHERE
date>=yesterday()-30
AND rights IN (0,4,5,10,14,15,20,24,25,30,34,35,40,44,45,50,54,55)
AND event IN ('Tab View', 'View', '', 'Home View')
AND client_id!=0
ORDER BY client_id, datetime

) GROUP BY client_id,date
) WHERE length(diffs)!=1

)
) GROUP BY client_id, date, cums

) GROUP BY date]]>

С точки зрения запроса к данным, мы считаем для каждого клиента (устройства) в каждую дату количество посещений страниц для каждого порядкового номера часа. Если таких посещений >1, то мы фиксируем показ WEBI.

Пример подсчета количества показов:

[macro]
Пример подсчета:
Предположим, мы зафиксировали у определенного пользователя в определенную дату такую последовательность в секундах между посещениями страниц сайта:

0, 20, 70, 4000, 300 (т.е. между открытием сайта и посещением следующей страницы прошло 20 секунд, между второй и первой - 70 секунд и т.д.)

Кумулятивная сумма:

0, 20, 90, 4090, 4390

Поделим каждый элемент последовательности на 3600 (приведение к "часам", округление вниз):

0, 0, 0, 1, 1

Теперь для каждого номера часа посчитаем количество посещений страниц:

Номер часа Количество посещений

0 3

1 2

Обработаем количество посещений с таким условием: если количество посещений в пределах часа >1, то мы показываем WEBI:

Номер часа Количество посещений Количество показов WEBI

0 3 1

1 2 1

Таким образом, суммарно за день пользователь увидит 2 показа WEBI

[/macro]

Данный способ подсчета имеет определенный недостаток - мы не знаем наверняка сделаны ли все просмотры в рамках нескольких сессий либо в рамках одной сессии.

В приведенном выше примере расчета эта неопределенность не сказалась бы на итоговом результате. Однако возможны случаи когда 1 показ будет не учтен (в ситуации когда пользователь провел на некоторой страницей более часа и будучи в этой же сессии перешел на новую страницу, а затем сразу вышел. Перед выходом он увидит WEBI, но этот показ ускользнет от подсчета, поскольку пользователь посетил всего 1 страницу в пределах часа.

Данная особенность подсчета обусловлена как раз отсутствием надежных данных о сессиях пользователей.

Динамика потенциальных показов WEBI показана на графике ниже:

Прогнозный средний CPM = $10

Медианное количество потенциальных показов в сутки составляет 407 000, что при CPM 10$ дает потенциальную суточную выручку в 407*10=4070$
