# EVALUATION PROTOCOL — Interstitials KB A/B (pre-registered)

Версия: **V0 (frozen 2026-08-04)**. Протокол зафиксирован ДО открытия holdout-карточек и ground truth. После открытия holdout пороги и критерии НЕ меняются; любое изменение возможно только как новая версия для нового теста, с фиксацией причин.

## 1. Primary comparison

**B против A.**

- **Плечо A:** `combined_validator_prompt.md` (frozen), вход = только blind holdout-карточка. Блок KNOWLEDGE CONTEXT отсутствует.
- **Плечо B:** тот же `combined_validator_prompt.md` (тот же байт-в-байт текст), вход = blind holdout-карточка + KNOWLEDGE CONTEXT (frozen `knowledge_base.md` + `pattern_cards.md`).
- Единственная разница между плечами — наличие knowledge base во входе. Любое другое расхождение (модель, температура, порядок карточек) — нарушение протокола.

## 2. Кейсы

Четыре holdout-кейса корпуса `interstitials-corpus-prep/holdout-blind/`: **IH-01, IH-02, IH-03, IH-04** (все четыре; выбор подмножества запрещён). Каждое плечо обрабатывает каждый кейс в чистом контексте (без памяти о других кейсах и другом плече).

## 3. Blind pairwise review

- Для каждого кейса ревьюер получает пару ответов (A, B) со снятой маркировкой плеча, в случайном порядке (лейблы «Ответ 1 / Ответ 2»; соответствие лейбл↔плечо фиксируется отдельно и вскрывается после всех вердиктов).
- Ревьюер на момент pairwise-вердикта не открывает ground truth, КРОМЕ шага «outcome alignment» (см. §4), который выполняется судьёй с доступом к ground truth ПОСЛЕ фиксации pairwise-предпочтения.
- Лимит человеческого review: **≤10 минут на кейс** (суммарно на пару ответов, без учёта outcome-alignment шага). Превышение фиксируется как нарушение критерия C7.

## 4. Критерии оценки (фиксируются на кейс)

| # | Критерий | Вопрос | Шкала |
|---|---|---|---|
| C1 | Новый product-specific insight | Даёт ли B продуктовый вывод про ЭТУ механику/сегмент/trigger, которого нет в A и который выводим только из knowledge base (с source ID)? | да/нет |
| C2 | Groundedness | Все исторические ссылки B имеют корректный source ID (KS-xx / IKB-xxx) и не искажают содержание источника; hallucinated lessons (ссылка на несуществующий/искажённый источник) = 0 | счёт нарушений |
| C3 | Relevance | Привлечённые аналоги релевантны кейсу (сходство механики/сегмента/поверхности объяснено, различия названы); нерелевантные притянутые аналоги штрафуются | да/частично/нет |
| C4 | Decision usefulness | Чей ответ полезнее владельцу решения (рекомендация, правки механики, дешёвый замер) — pairwise-предпочтение | A / B / tie |
| C5 | Outcome alignment | Чьи продуктовые опасения/рекомендации лучше согласуются с фактическим исходом эксперимента (по ground truth, вскрывается после C1–C4, C6) | A / B / tie |
| C6 | Safety / unsupported transfer | Переносы lessons без поддержки источника или через явные «не переносить»-границы KB; unsupported transfers = 0; single-case применён без оговорки — нарушение | счёт нарушений |
| C7 | Review cost | Человеческий review ≤10 минут на кейс | да/нет |

## 5. Правила false blocker

- **False blocker** = рекомендация плеча (`revise`/`deprioritize` или продуктовый вердикт «сомнительна»), которая по ground truth блокировала бы гипотезу, оказавшуюся успешной (rollout / положительный фактический исход), при том что названные причины блокировки фактическим исходом не подтвердились.
- Считается по каждому плечу отдельно, после вскрытия ground truth.
- Условие для YES: **число false blockers у B ≤ числа false blockers у A.** Рост ложных блокировок из-за knowledge base — прямое поражение B по этому пункту.
- Блокировка, чьи причины подтвердились исходом (эксперимент реально провалился по названному механизму), false blocker'ом не является.

## 6. Итог `YES` (польза KB подтверждена) — все условия одновременно

1. B предпочтён по C4 (decision usefulness) минимум в **3 из 4** кейсов (tie не засчитывается за B).
2. B даёт новый source-grounded продуктовый insight (C1 = да, с корректными source ID по C2) минимум в **3 из 4** кейсов.
3. Минимум в **одном** кейсе B **существенно** меняет решение относительно A: другую идею, сегмент, механику, guardrail, stop-rule или приоритет (не только формулировки).
4. **Hallucinated lessons (C2) = 0** во всех ответах B.
5. **Unsupported transfers (C6) = 0** во всех ответах B.
6. Ложных блокировок хороших идей у B **не больше**, чем у A (§5).
7. Human review ≤10 минут на кейс (C7 = да для всех кейсов).

Невыполнение любого условия → итог `NO` (или `NO, с оговорками` при выполнении 1–2 и провале только 7 — фиксируется, порог не пересматривается). Пороги после открытия holdout не меняются.

## 7. Фиксация результатов

Для каждого кейса сохраняются: оба ответа, лейбл-маппинг, вердикты C1–C7 с одним предложением обоснования каждый, время review, итоговая таблица 4 кейсов и вывод YES/NO. Отчёт пишется агентом A/B-задачи (FLOW-570), не этим билдером.
