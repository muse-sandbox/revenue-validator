Применяю Combined Validator + Product Review Prompt V0 к документу IH-04. Knowledge context во входе отсутствует (плечо A), поэтому в проходе 3 исторические аналоги не оцениваются.

**TLDR: рекомендация — `revise` (уверенность medium).** Модель денег держится на одном необоснованном допущении — free-surface конверсия «held flat» при росте первой цены с $19.99 до $29.99 (+50%), при том что документ сам флагует этот риск, а его же прецедент показывает эластичность в противоположную сторону (дешевле → конверсия выше). Winback-часть модели обоснована лучше. Плюс внутреннее противоречие в forecast-числах ($463/день против $1,183/день) и незаполненный порог ARPU в самой гипотезе.

## ПРОХОД 2: Критерии и рекомендация

**1. Рекомендация:** `revise`, уверенность **medium** — критичный concern по К1/К2 (free-конверсия зафиксирована константой при +50% цене без обоснования) при в остальном сильном дизайне.

**2. Обоснование.** ~73% прогнозируемого прироста (+$547 из +$747/день) приходится на free surface, где весь gain держится на допущении S7(а): конверсия 0.67%/0.33% не изменится при росте первого платежа $19.99→$29.99. Это допущение без evidence, документ сам флагует его как риск, а единственный прецедент instant-оффера в документе — про снижение цены на узком сегменте, т.е. по переносимости не поддерживает рост цены. Winback-половина, напротив, обоснована декомпозицией дырявого trial-этапа (fact) и имеет запас: modeled +88.3% против breakeven +33%. Дизайн эксперимента добротный (MDE по денежной метрике, CUPED, reach замерен, sample достижим), поэтому пробелы исправимы — это revise, не deprioritize.

**3. Ожидаемая incremental revenue.** Прогноз автора: ≈ +$747/день (+63%) на restricted-аудитории при 100% rollout (S6); альтернативный фрейм автора же — +$46/день как «+10% floor» от противоречащей базы $463/день (S14-1). Реалистичный диапазон валидатора: winback-часть ≈ [0; +$200/день] (breakeven при conv +33%, направление поддержано декомпозицией S7(б)); free-часть — знак не определён: при падении конверсии >~38% iOS / ~40% Android (производное: 1−12.99/20.99; 1−15.31/25.49) вклад становится отрицательным. Суммарный диапазон не восстановим, потому что в документе нет ни одного замера ценовой эластичности для роста цены — только для снижения.

**5. Критичные допущения.** (а) free members→buyer flat при +50% цене — assumption, несёт ~73% прогнозируемого gain; (б) winback conv +88.3% — forecast, запас до breakeven большой, но величина не обоснована; (в) ARPPU $20.99/$25.49 — forecast, производное от цены (чувствительно к refund-допущениям, в документе не раскрыты).

**6. Каннибализация / refunds / guardrails.** Оффер замещает два существующих денежных потока (intro $19.99 и trial→$39.99) — потеря первого из них при просадке free-конверсии есть главный незамоделированный минус. Refunds: гипотеза обещает «quality не ухудшится», guardrails на charge→14d cancel/refund объявлены — но при цене $29.99 без trial у новичков refund-риск направленно выше, чем в прецеденте с дешёвым планом. Каннибализация основного paywall не оценена (S3).

**7. Stop-rule.** В документе отсутствует. Предложение валидатора (пометка: предложение): остановка/откат, если free-surface members→buyer падает статзначимо сильнее ~38% (breakeven-порог из собственной модели документа) либо charge→14d refund растёт значимо против контроля.

**8. Что изменит рекомендацию.** В сторону `launch`: (а) обоснование free-эластичности любым замером документного уровня (см. проход 3 п.4) или замена «flat» на консервативный диапазон с сохранением положительного net; (б) устранение противоречия $463 vs $1,183/день; (в) заполненный числовой порог гипотезы; (г) описание плеча C и фиксация stop-rule + post-rollout плана. В сторону `deprioritize`: evidence, что free-конверсия при +50% цене падает за breakeven (~38–40%) — тогда net-эффект держится только на winback (+$200/день максимум), и нужен явный бизнес-порог, которого в документе нет.

**9. Missing:** числовой порог ARPU в гипотезе («XX%»); содержимое плеча C; строка потерь free-конверсии числом; оценка каннибализации основного paywall; post-rollout протокол (S12); stop-rule (S13); инструмент замера reach; refund-допущения внутри ARPPU-прогноза.

## ПРОХОД 3: Продуктовый review

**1. Оценка механики + главный риск.** Механика — замена оффера на двух живых interstitial-поверхностях (daily slot + ad-fail fallback, trigger/frequency нетронуты, S2/S3): единый instant-план $29.99 без trial. Расчёт на поведение «плата вперёд = фильтр intent». Для winback-сегмента механизм правдоподобен из самого документа: бывшие подписчики знают продукт, а trial-этап у них доказанно дырявый (19.5%/17.7% trial→charge, fact) и притягивает re-trialists (early cancels +69–118% в прошлом тесте). Для free-сегмента механизм сомнителен: это новички сразу после install tour, у которых убирают и trial, и низкую входную точку, поднимая первый платёж на +50% — «фильтр intent» здесь может отфильтровать почти всех. **Главный продуктовый риск: один оффер натянут на два противоположных сегмента — то, что чинит воронку winback (убрать trial), одновременно поднимает барьер новичкам, не готовым платить $29.99 за незнакомый продукт.**

**2. Исторические аналоги.** Knowledge context не предоставлен — исторические аналоги не оцениваю.

**3. Product-specific recommendation.**
1. Развязать оффер по поверхностям: для winback сохранить instant $29.99 (поддержано декомпозицией воронки контроля в документе); для free surface рассмотреть instant по текущей входной цене ~$19.99 — все внутридокументные прецеденты instant-механики работают через снижение или сохранение цены, ни один — через рост.
2. Использовать неописанное плечо C именно под это: B = instant $29.99 на обеих поверхностях (текущий план), C = instant $19.99 на free + $29.99 на winback — тогда эксперимент сам измерит free-эластичность вместо допущения «flat».
3. Довести guardrail «free-surface members→buyer не падает» до решения-правила с числом: порог − 38% (breakeven из модели документа), а не просто «watch».
4. Сохранить как есть: trigger/frequency/creative (в документе явно заморожены — это чистый тест оффера) и раздельное чтение поверхностей (S11).

**4. Самый дешёвый решающий замер.** SQL-разрез по данным прошлого free-surface теста (Pre-launch п.1): конверсия members→buyer в ячейке intro-плана $19.99 против ячейки/периода с более высокой ценой первого платежа — это даёт единственную доступную из документа точку ценовой эластичности free-аудитории вверх по цене. Подтверждено: историческое падение конверсии при сопоставимом росте цены заметно меньше ~38% — допущение «flat/умеренное падение» жизнеспособно, модель остаётся net-положительной. Опровергнуто: падение ≥ ~38–40% — free-ветка меняет знак, оффер для free нужно пересобирать (п.3.1) до запуска.

**5. Численные vs продуктовые concerns.**
- Численные (проход 2, только ссылки): К1 критичный, К2 критичный, К3 средний, К6 средний; противоречие S14-1.
- Продуктовые: (а) один оффер на два разнонаправленных сегмента; (б) $29.99 без trial как первый контакт новичка с платным продуктом; (в) плечо C не использовано для снятия главной неопределённости; (г) refund-риск у no-trial-покупки новичков.
- Связи: продуктовый (а)+(б) и численные К1/К2 — это один и тот же риск с двух сторон, они усиливают друг друга; продуктовый (г) усиливает К3 (потери/refunds); (в) независим от прохода 2 и является самым дешёвым способом закрыть К1/К2 внутри самого эксперимента; К6 независим от всех продуктовых.
