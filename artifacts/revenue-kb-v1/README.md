# Revenue Knowledge Base V1 (FLOW-578)

Замороженная база знаний по завершённым revenue-экспериментам UG,
организованная по **продуктовой причинности** (этапы flow → механизмы →
сегменты → measurement-гейты), а не как список экспериментов. Построена для
A/B-оценки пользы KB на blind holdout
(`../revenue-corpus-prep-v1/EVALUATION_PROTOCOL.md`, FLOW-575) и как рабочий
KNOWLEDGE CONTEXT валидатора пре-лонч идей.

Дата freeze: **2026-08-04**. После freeze файлы не меняются; изменения — только
как новая версия с новым манифестом.

## Организация базы (DoD FLOW-578)

- **Группировка по причинности:** паттерны сгруппированы по этапам Revenue
  User Flow (FLOW-576, S0–S9): exposure/reach (S3–S4) → структура воронки
  (S3–S5) → структура оффера и цена (S5–S6) → сегменты и lifecycle (S2, S8) →
  measurement-гейты (сквозные). Индексы в `knowledge_base.md` §3 дают разрезы
  по этапу, сегменту, механизму и типу решения.
- **Уровень близости:** каждая карточка-источник несёт страту относительно
  якоря (type1/2/3); близость к валидируемому кейсу пересчитывается по
  правилам L1–L3 (§2 `knowledge_base.md`), формат analog-карточки с
  обязательным непустым `not_transferable`.
- **Каждый паттерн:** факт (с числами и p-values), источник (ID кейса +
  validity-класс), механизм, применимость, запреты на перенос.
- **Уроки бывших holdout Interstitials-кейсов** (IH-01…IH-04 из FLOW-568/571,
  сожжены в development set) включены как T1-07…T1-10 и держат четыре
  обязательных паттерна задачи: P-11 (goal-метрика = затронутая поверхность),
  P-12 (delivery/exposure как pre-launch gate), P-10 (персонализировать
  оффер, а не обёртку), P-07 (ограничения паттерна «цена не двигает выручку»).

   `interstitials-corpus-prep/knowledge-sources/`, зеркало

## Дисклозы (честность построения)

1. **Builder видел однострочные исходы holdout-кейсов** до чтения
   EXCLUSION_MANIFEST: путь к манифесту находится только через итоговый
   Linear-комментарий FLOW-575, который содержит таблицу со стратами и
   краткими классами исходов RH-01…06. Это bootstrap-неизбежность той же
   природы, что зафиксированная в FLOW-575 оговорка «составитель видел
   исходы»: гарантия — детерминированность правил и полное исключение этих
   кейсов из KB, а не «незнание». В KB нет ни одного факта, урока или
   паттерна, опирающегося на holdout-кейсы.
2. **При зачистке кросс-ссылок** builder видел 5 строк с краткими
   парафразами уроков исключённых кейсов (линии winback/меню планов). Все
   парафразы вычищены; соответствующие утверждения в KB опираются только на
   собственные страницы разрешённых кейсов (T3-03, T3-05).
3. Разметка входа (V0.1) сверена с Confluence-страницами агентно
   (FLOW-577), но финальной сверки человеком-аналитиком не было.

## Ограничения покрытия (унаследованы от FLOW-577 V0.1)

- **Tour/onboarding paywall (S3)** — главная конверсионная поверхность App —
  не представлена ни одним кейсом: идеи этого класса будут находить только
  L2-аналоги (interstitial-слой). Валидатор обязан говорить об этом явно.
- **Lifecycle S7–S8** (trial length, price increase, refund/cancel-flow,
  pause) — единственный кейс T2-05.
- Ось offer всюду Pro/Pro+ — нет OTP / songbooks / courses; вход из CRM/push
  (S1) не представлен.
- 4 из 18 кейсов inconclusive → только measurement-уроки; корпус после
  исключения holdout смещён: линия «та же поверхность, другие итерации»
  (страта 1) урезана до сожжённых и ранних кейсов.
