# HX-02 — pre-launch карточка
(без идентификаторов источника)

## Контекст и цель
Цель — увеличить revenue retention на вебе. Идея: информировать пользователей, которые отменили автопродление подписки и у которых скоро заканчивается доступ, о скорой потере премиум-преимуществ. Упоминается, что существует аналогичный проект для мобильных приложений (описательно, без деталей).

## Предлагаемое изменение (что именно меняем, для кого, где)
За две недели до окончания доступа показывать неубираемый (non-dismissible) постоянный баннер с обратным отсчётом до конца доступа. Текст баннера сообщает, что подписка заканчивается, и предлагает сохранить доступ. По клику на баннер открывается модальное окно со списком фич, которые пользователь потеряет, если не продлит доступ. Так как платёжные данные пользователя уже сохранены, повторно их не запрашиваем: клик по кнопке в модалке включает автопродление текущей подписки (с подтверждением). После активации показывается окно успеха, затем возврат на исходную страницу; баннер скрывается. Статус подписки в разделе Subscriptions меняется на «Active» с кнопкой «Details»; должна появиться кнопка «Manage» с возможностью снова отменить «восстановленную» подписку. FAIL-ветка: если создание новой подписки в биллинг-провайдере не удаётся, повторяем попытки без участия пользователя; после исчерпания попыток информируем пользователя (например, письмом с кнопкой повторного создания подписки).

## Аудитория / платформа / сценарий
Веб. Пользователи, отменившие автопродление, но ещё имеющие активный доступ, у которых доступ истекает в ближайшие две недели. Только те, кто купил доступ на вебе; купившие доступ в приложении в эксперимент не включаются. Первая итерация — только подписка PRO (EDU, PRO+Courses, Songbooks помечены как «следующая итерация»). В документе оставлен открытый вопрос-заметка: «нужны цифры по целевым пользователям, которые с доступом и без авто-ренью и которые заходят в последние две недели; сколько из них изначально взяли доступ в приложении» (данные на момент запуска — `missing`).

## Денежная модель (цепочка поведение→деньги, все коэффициенты)
Модель A/B теста (на 566 пользователей в каждой группе):
- A (без баннера): реактивации 5, charges 5, Banner → Access 0.88%, Revenue $265, ARPU $0.47, ARPPU $53.0
- B (с баннером): реактивации 31, charges 31, Banner → Access 5%, Revenue $1293, ARPU $2.05, ARPPU $41.6
- diff: +26 реактиваций, +26 charges, +468% по конверсии, +$1028 Revenue, +$1.58 ARPU, −$11.4 ARPPU
Цепочка: показ баннера → клик → модалка → включение автопродления (реактивация) → charge по сохранённым платёжным данным → revenue.
