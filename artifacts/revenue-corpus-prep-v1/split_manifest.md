# Split Manifest — Revenue Holdout V1 (FLOW-575)

**Заморожено: 2026-08-04.** После этой фиксации состав holdout не меняется.

## Контекст

Holdout формируется ДО сборки Knowledge Base V1 из корпуса FLOW-577
(24 завершённых revenue-эксперимента, все `verified-card` после сверки с
Confluence 2026-08-04, inventory V0.1). Стратификация задана задачей FLOW-575:
по 2 кейса из каждого из трёх типов близости к якорю (семейство UG App
monetization interstitials, FLOW-568).

## Правило отбора (зафиксировано до формирования, детерминированное)

1. Единица корпуса — Confluence-страница проекта (итерации внутри страницы —
   один кейс). Вселенная: 24 кейса inventory FLOW-577 V0.1.
2. **Сожжённые кейсы неприемлемы** (уже участвовали в оценках и стали
   development set): T1-07, T1-08, T1-09, T1-10 — это IH-01..IH-04 предыдущего
   Interstitials-holdout, использованного в A/B-тесте KB V0 (FLOW-570/571) и в
   аудите FLOW-584. Проверено также отсутствие пересечения с корпусом бэктеста
   Validator V0 (HX-01..HX-08, FLOW-546/565): пересечений нет (другие pageId —
   tour/PDF/registration/CRM-эксперименты).
3. Внутри каждой страты (type1 / type2 / type3) выбираются **2 наиболее поздних
   по дате запуска проектной страницы** (дата `[YYYY-MM-DD]` в заголовке
   Confluence-страницы — та же конвенция сортировки, что в split_manifest FLOW-568).
4. Гейт пригодности: исход кейса документирован на первичной странице
   (после сверки FLOW-577 это выполняется для всех кандидатов — UNVERIFIABLE
   кейсов не осталось, скольжения окна не потребовалось).
5. Размер (2 на страту) задан текстом задачи FLOW-575 до отбора.
6. Выбор не зависит от исходов: сортировка чисто временная, формула размера
   фиксирована извне.

## Следствие для Knowledge Base V1 (обязательное)

RH-01/RH-02 (= T1-05/T1-06) были knowledge-источниками KS-05/KS-06 в KB V0.
Поэтому при сборке KB V1:

1. записи T1-05, T1-06, T2-03, T2-04, T3-04, T3-07 **удаляются из входного
   inventory** (см. `EXCLUSION_MANIFEST.md`);
2. builder KB V1 **не читает бандл KB V0** (`interstitials-kb-v0/` —
   knowledge_base.md и pattern_cards.md содержат исходы KS-05/KS-06) и
   каталог `interstitials-corpus-prep/knowledge-sources/` (KS-05/KS-06);
3. запрет на зеркало `context/hypotheses/`, реестровое поле
   `success_variation` и исходные страницы holdout сохраняется (как в FLOW-568).

## Примечание о блайндинге процесса

Готовивший holdout агент видел исходы всех кандидатов (он же выполнял сверку
FLOW-577). Гарантия отсутствия cherry-picking — **детерминированность правила**
(страта задана задачей, сортировка по дате страницы, размер фиксирован), не
«незнание» готовившего. Та же модель, что в FLOW-568 (см. его split_manifest).
