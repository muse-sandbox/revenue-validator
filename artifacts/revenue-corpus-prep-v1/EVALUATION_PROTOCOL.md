# EVALUATION PROTOCOL — Revenue Holdout V1 (pre-registered, FLOW-575)

Версия: **V1 (frozen 2026-08-04)**. Протокол зафиксирован ДО первого inference-прогона
на этом holdout и ДО сборки Knowledge Base V1. После начала любого прогона пороги и
критерии НЕ меняются; изменение возможно только как новая версия для нового теста,
с фиксацией причин. Протокол наследует структуру `interstitials-kb-v0/EVALUATION_PROTOCOL.md`
(V0, FLOW-569) с масштабированием 4 → 6 кейсов и добавлением стратной оси.

## 1. Primary comparison

**B против A** (польза Knowledge Base V1):

- **Плечо A:** frozen combined validator prompt (версии V1; фиксируется хешем в
  FREEZE_MANIFEST бандла KB V1), вход = только blind holdout-карточка. Блок
  KNOWLEDGE CONTEXT отсутствует.
- **Плечо B:** тот же prompt байт-в-байт, вход = blind holdout-карточка + KNOWLEDGE
  CONTEXT (frozen KB V1 в составе, который зафиксирует его FREEZE_MANIFEST).
- Единственная разница плеч — наличие knowledge base во входе. Любое другое
  расхождение (модель, температура, порядок кейсов) — нарушение протокола.
- Каждый запуск — чистый изолированный контекст (без памяти о других кейсах и
  другом плече), headless, инструменты и MCP отключены — по образцу FLOW-570
  (`run_manifest.md` бандла `interstitials-kb-ab-run`).

## 2. Кейсы

Шесть holdout-кейсов `revenue-corpus-prep-v1/holdout-blind/`: **RH-01…RH-06**
(все шесть; выбор подмножества запрещён). Стратификация: RH-01/02 — страта 1
(тот же слой, что якорь), RH-03/04 — страта 2 (тот же этап flow, другая
поверхность), RH-05/06 — страта 3 (та же метрика, другой flow/механизм).
ID раскрывает страту намеренно — это ось анализа переносимости; исходов не раскрывает.

## 3. Blind pairwise review

- Для каждого кейса ревьюер получает пару ответов (A, B) со снятой маркировкой,
  в случайном порядке («Ответ 1 / Ответ 2»); mapping лейбл↔плечо хранится отдельно
  (sealed) и вскрывается после всех pairwise-вердиктов.
- Ревьюер не открывает ground truth до шага outcome alignment (§4/C5), который
  выполняется судьёй ПОСЛЕ фиксации pairwise-предпочтений C1–C4, C6.
- Лимит human review: **≤10 минут на кейс** (пара ответов, без outcome-alignment).
- Известное ограничение дизайна (унаследовано из FLOW-570): verbatim-ответы могут
  выдавать плечо содержательно (B цитирует source ID). Имена файлов и порядок
  пары плечо выдавать не должны.

## 4. Критерии на кейс (C1–C7)

Идентичны V0-протоколу: C1 новый product-specific insight (да/нет, только с
корректным source ID); C2 groundedness (hallucinated lessons = счёт нарушений);
C3 relevance привлечённых аналогов; C4 decision usefulness (pairwise A/B/tie);
C5 outcome alignment (по ground truth, после C1–C4/C6); C6 unsupported transfer
(счёт нарушений; single-case без оговорки — нарушение); C7 review cost ≤10 мин.

Дополнение V1 (стратная ось): для C1/C3 фиксируется, из какой близости взяты
привлечённые аналоги; ожидание — в страте 3 корректный ответ ссылается на
guardrails/measurement-уроки, а НЕ переносит продуктовые величины (правило L1–L3
модели FLOW-574). Перенос продуктового вывода без оснований в страте 3 — нарушение C6.

## 5. False blocker

Определение и правило V0 без изменений: рекомендация плеча, блокирующая гипотезу,
чей фактический исход оказался успешным (rollout/позитив), при неподтверждённых
причинах блокировки. Условие: **false blockers у B ≤ у A** (по каждому плечу,
после вскрытия ground truth). Блокировка с подтвердившимися причинами false
blocker'ом не является.

## 6. Итог `YES` (польза KB V1 подтверждена) — все условия одновременно

1. B предпочтён по C4 минимум в **4 из 6** кейсов (tie не в счёт B).
2. C1 = да (source-grounded insight, корректные ID) минимум в **4 из 6** кейсов,
   **включая хотя бы один кейс страты 2 или 3** (иначе KB доказала пользу только
   на самой близкой переносимости — фиксируется как `YES-NARROW`).
3. Минимум в **одном** кейсе B существенно меняет решение против A (идея, сегмент,
   механика, guardrail, stop-rule, приоритет — не формулировки).
4. Hallucinated lessons (C2) = **0** во всех ответах B.
5. Unsupported transfers (C6) = **0** во всех ответах B (включая стратное правило §4).
6. False blockers у B ≤ у A (§5).
7. Human review ≤10 мин на кейс (C7 = да для всех).

Невыполнение любого условия → `NO` (или `NO, с оговорками` при выполнении 1–2 и
провале только 7). `YES-NARROW` — отдельный зафиксированный исход: KB полезна, но
только в ближней страте; для решения о расширении корпуса, не для отказа от KB.
Пороги после открытия holdout не меняются.

## 7. Фиксация результатов

На кейс: оба ответа verbatim, лейбл-mapping, вердикты C1–C7 (по одному предложению
обоснования), время review; итоговая таблица 6 кейсов × страты, вывод
YES / YES-NARROW / NO. Отчёт пишет агент прогона/оценки, не составитель корпуса.
